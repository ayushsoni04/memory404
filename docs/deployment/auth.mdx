memory404 authenticates users entirely on its own — passwords hashed and stored in MongoDB, sessions as signed JWTs, password-reset emails via Resend. No third-party identity provider is involved. Every vault (links + groups) is private to the signed-in user.

## How it works

- **Passwords**: hashed with Node's built-in `crypto.scrypt` (`lib/password.ts`) — never stored or logged in plaintext.
- **Sessions**: a signed HS256 JWT with payload `{ userId }`, valid for 14 days (`lib/session.ts`).
  - **Browser**: httpOnly cookie `m404_session` (`sameSite=lax`, `secure` in production). `proxy.ts` redirects signed-out visitors to `/login` for pages outside the public allowlist.
  - **Chrome extension / Express**: same JWT returned as `token` from `POST /api/auth/login` (and signup). Clients send `Authorization: Bearer <token>`.
- **API ownership**: `requireAuth()` (`lib/auth.ts`) resolves cookie or Bearer and returns **401** when neither is valid. All vault APIs scope reads/writes by `auth.id`.
- **Signup/login/logout/password-reset**: Route Handlers under `app/api/auth/*`.
- **Profile**: `GET`/`PATCH`/`DELETE /api/me` and `POST /api/me/password` persist name, username, banner, and avatar in MongoDB.

## Environment variables

```bash
SESSION_SECRET=   # openssl rand -base64 32 — server-only, never NEXT_PUBLIC_
RESEND_API_KEY=   # from resend.com — server-only
EMAIL_FROM=       # optional; production verified sender, e.g. memory404 <noreply@yourdomain.com>
```

Set these in `.env.local` for development and in Vercel for production. Rotating `SESSION_SECRET` invalidates every existing session and extension token.

`AUTH_BYPASS=1` skips the page login gate in **development only**. It is ignored when `NODE_ENV=production`. Do not set it on production hosts.

`/api/auth/dev-skip` ("Skip for now") is also disabled in production.

## Password-reset email (Resend)

1. Create an account at [resend.com](https://resend.com) and generate an API key.
2. Set `RESEND_API_KEY`.
3. For production, [verify your domain](https://resend.com/docs/dashboard/domains/introduction) and set `EMAIL_FROM` to that verified address. Without `EMAIL_FROM`, mail sends from Resend's sandbox `onboarding@resend.dev` (fine for local testing, not for real users).

If `RESEND_API_KEY` is unset, `sendPasswordResetEmail` logs and no-ops — `/forgot-password` still returns success (non-enumerating).

## Password policy

Enforced in two places that must stay in sync:

- Client-side hint: `lib/password-policy.ts` (`PASSWORD_MIN_LENGTH`, `getPasswordRequirementIssues`)
- Server-side: `app/api/auth/signup/route.ts`, `app/api/auth/reset-password/route.ts`, and `app/api/me/password/route.ts`

Current policy: at least 8 characters, with an uppercase letter, a lowercase letter, and a number.

## Rate limits

Login, signup, forgot-password, and reset-password are rate-limited per IP (in-memory, per instance). Burst callers receive `429`.

## Chrome extension

1. Set **App URL** to your memory404 origin.
2. Sign in with email/password in the popup (stores Bearer token in `chrome.storage.local`).
3. Saves and group fetches send `Authorization: Bearer …` so data lands in that user's vault.

## Express backend

When using the standalone Express API, send the same Bearer token. Unauthenticated requests receive `401`. Prefer same-origin Next.js `/api/*` in production when possible.

## What's not built yet

OAuth (Google/GitHub/X) is deferred — plan is [`arctic`](https://arcticjs.dev). Until then, email/password is the only sign-in method. Public profile pages and billing are also out of scope for the current private-vault multi-user release.
